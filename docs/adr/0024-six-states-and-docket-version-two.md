# ADR 0024 — 状態の区分を 6 つに固定し、台帳の版を 2 に上げて前の実行ファイルを止める

- 状態: **受理**（Issue #120・施主 2026-11-09「推しで」）
- 日付: 2026-11-09
- Issue: #120
- 影響する規則: FR-001 / ADR 0004（追記専用と併合）/ ADR 0010（`docket.v1.txt`）/ ARC-009（移行）/ FR-014（黙って捨てない）

## 文脈

運用の筋書き（Issue #115・[docs/design/2026-11-09-operating-scenario.md](../design/2026-11-09-operating-scenario.md)）の 5 段「閉じる」は、担当が「確認中」にし、確認者が見て「完了」にする。止めた課題は「保留」、やめた課題は削除ではなく「中止」で閉じる。状態は 3 つ（未着手・着手中・完了）しか無かった。区分は PR #108 の方針 2.1 で 6 つに固定すると決めてある（名前の付け替えは段階 1）。

新しい状態はジャーナルの行に新しい語（`review` / `on_hold` / `cancelled`）で入る。前の実行ファイルはその行を知らない語として「読めなかった行」に数え、課題の状態が古いまま表に出る。**データが消えたように見える**のが方針の最大のリスクの 2 つ目（PR #108 第 6 節）。

## 決定

1. **状態は 6 つ**: 未着手（`open`）・対応中（`in_progress`・表示を「着手中」から改めた）・確認中（`review`）・保留（`on_hold`）・完了（`done`）・中止（`cancelled`）。閉じた集合（RS-002）
2. **閉じた状態は完了と中止**（`ItemState::is_closed`）。「完了も表示」を外すと両方が表から外れ、行は灰色で残り、期限超過の印を付けない。完了日（ADR 0023）は完了だけ
3. **台帳の版を 2 にする**: `docket.v1.txt` の `version = 2`。ファイル名は変えない（変えると前の実行ファイルが同じフォルダに版 1 の台帳を新しく作り、別の台帳として書き始める）。前の実行ファイルは `version != 1` を「読めない版」として起動を止める（Issue #9 からの約束）
4. **新しい実行ファイルは開いたときに版 1 を版 2 に書き直す**（`DocketFile::upgrade_in`）。誰が開いても書き直す。中身は同じなので、2 台が同時に書いても同じ結果。新しい状態の行を書く前に古い読み手が止まる
5. ジャーナル・スナップショット・設定の形は変えない（状態の語が 3 つ増えるだけ）

## 帰結

- 得たもの: 筋書きの 5 段「閉じる」が回る。中止は削除と違って行が残り、なぜやめたかを本文と履歴で読める
- 失ったもの: **チームの全員が同時に新しい実行ファイルへ替える必要がある**。1 台でも新しい実行ファイルが開けば、前の実行ファイルは「unknown docket version `2`」で止まる（どの機械を更新すればよいかは分かる）
- 権限を有効にした台帳でも `docket.v1.txt` は署名の外なので、編集者が書き直してよい（持ち主の権限の欄は読んだ値をそのまま書く）。持ち主の権限の変更と同じ瞬間に書き直しが重なると、後に rename した方が残る（どちらも中身を読み直して書くので、窓は 1 回の読みと書きの間だけ）

## 検討した案

| 案 | 却下の理由 |
| --- | --- |
| 版を上げずに語を足す | 前の実行ファイルが新しい状態の行を黙って捨て、課題の状態が古いまま出る（データが消えたように見える） |
| 新しい状態の行を初めて書くときに版を上げる | 版を上げる前に別の機械の前の実行ファイルが開いていると、その後の行を読めない時間ができる。開いたときに上げる方が単純で、止まる時点がはっきりする |
| ファイル名を `docket.v2.txt` にする | 前の実行ファイルは `docket.v1.txt` が無いと新しく作り、同じフォルダに別の台帳ができる |
| 中止を作らず削除で済ませる | 完了率と完了日の意味が変わる。削除は表から消え、なぜやめたかが残らない（PR #108 第 4 節の裁定） |
