# ADR 0022 — 採用した見た目: 枠なし窓・共有ビューのタブの帯・表示の切り替え・詳細のペイン・色の札 14

- 状態: **受理**（Issue #109・施主 2026-10-22「よさそうだね。この方向性で詰めていってほしい」と 3 点の決定）
- 日付: 2026-10-22
- Issue: #109
- 影響する規則: FR-012 / FR-016 / FR-018（改める）/ ARC-011 / ADR 0002 / ADR 0006 / ADR 0009 / ADR 0012 / ADR 0021

## 文脈

施主 2026-10-22「OS 依存のヘッダーや枠をなくして NeNeNib や NeNeFolio と同じアプローチでデザインを詰めてほしい」「/design を使ってレイアウトを詰めて、NeNeNib ライクで且つ、クールで使いやすいレイアウトデザインを練り上げて」。

いまの FR-018 は「窓は OS の通常の窓。枠・タイトルバー・最小化・最大化は OS に任せる。nene-ruler と違い、飾りなしにはしない」。窓は `WS_OVERLAPPEDWINDOW` の素の窓で、上に道具の行、下に編集行と段（本文・参加者・添付・履歴）を出し入れする。

NeNe Nib は Claude の `/design` で見た目を起こして施主が承認し（Nib ADR 0008）、枠を自分で消した `WS_OVERLAPPEDWINDOW` に 40 DIP のタブの帯と 28 DIP のステータスバーを描く。NeNe Folio も枠なし窓で、`WM_NCACTIVATE` / `WM_NCPAINT` を自分で答える（Folio ADR 0011 / 0014）。同じ形を Docket に当て、8 枚を描いた（[採用案](../design/2026-10-22-look.md)）。

## 決定

1. **見た目の正本は [docs/design/2026-10-22-look.md](../design/2026-10-22-look.md) の寸法と色の札、画は [docs/design/look/](../design/look/)。** UI はそれを写す
2. **FR-018 を改める: 窓は枠なし。** OS の枠とタイトルバーを消し、帯と窓の操作を自前で描く。Snap・影・最小化と最大化のアニメーションは OS のまま残す。Windows は Nib の決定 2 と同じ作り（`WS_OVERLAPPEDWINDOW` ＋ `WM_NCCALCSIZE` に 0・`WM_NCHITTEST` と `WM_NCACTIVATE` は自前・最大化のはみ出しは縁の分だけ内側へ）。X11 は `_MOTIF_WM_HINTS` で飾りを外し、移動と大きさの変更は `_NET_WM_MOVERESIZE` で WM に頼む
3. **帯（40）のタブは共有ビュー**（ADR 0021 の決定 5）。右に表示の切り替え（表・両方・詳細）・ヘルプ・台帳の設定・窓の操作
4. **編集は右の詳細のペインへ移す。** 下の編集行と段をやめる。ペインの幅は既定 380 で、**境のドラッグで 300〜640**、設定に保存する（施主の決定 2）
5. **色の札を 8 から 14 にする**（`title_bar`・`status`・`pane`・`line`・`field`・`accent_text`・`check`・`synced` を足し、`surface` を `field` に、`ink` を `text` に名前を合わせる）。配色 125 はいまと同じく 3 色から整数の補間で導く。**`synced`（同期の点・完了の点）も配色ごとに導く**（施主の決定 3）
6. **印刷の帳票に作成・確認・承認の印の欄を入れる**（施主の決定 1）
7. ヒットテストと配置は純関数（core / application）。窓の手続きは座標を渡して結果を写すだけ（ADR 0006・ARC-011）

## 強制

- planned: すべて。段階ごとの Issue で、測れるものから active にする（窓の枠と帯 → 詳細のペイン → 色の札 14 → 定例・印刷・Ctrl+P は ADR 0021 の段階に合わせる）
- planned: 帯・ペイン・タブのヒットテストの単体テスト。Windows の Snap・影・最大化の縁と X11 の WM ごとの振る舞いは施主の実機で記録する（QLT-013）

## 結果

- 得たもの: Nib・Folio と揃った見た目。縦の幅を帯 1 本に収め、表と詳細を並べて見られる。編集が下の 1 行から、項目の多い課題管理表に合うペインになる
- 失うもの: 非クライアント領域のメッセージを自分で扱う（Windows）。X11 は WM 次第で Snap と影が効かないことがあり、2 OS で同じ手触りにはならない
- 残る穴: X11 の枠なしは WSLg で確かめるまで「動く」と書かない。125 の配色で増やした札が地に対して読めるかは、導く式を決めてから全配色で測る。狭い窓でのペインの畳み方は未定

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| OS の窓のまま（いまの FR-018） | 施主の指示（OS 依存のヘッダーや枠をなくす）と、Nib・Folio と揃える方針に反する |
| `WS_POPUP` の窓 | Snap・影・アニメーションが無い（Nib ADR 0008 の却下と同じ） |
| 編集を下の段のまま | 項目が増える（ADR 0021）と 1 行に収まらない。表と詳細を並べて見られない |
| 同期の色を固定の緑 | 125 の配色の中で浮く。施主の決定 3 |
