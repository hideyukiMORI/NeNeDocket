# ADR 0010 — 権限を有効にした台帳では、操作の行に Ed25519 の署名を付け、読み手が公開鍵で検証する

- 状態: 提案（施主の判断待ち: 外部クレートの追加と BSD-3-Clause の許可）
- 日付: 2026-10-21
- Issue: #25
- 影響する規則: ARC-009 / ARC-010 / ARC-013 / RS-016 / QLT-010 / CNF-013。ADR 0004 の 10 を実装する

## 文脈

FR-010: 権限とグループを設定できる。設定しなければ誰でも編集できる。FR-009: アカウントはローカルの乱数の ID で、パスワードは無く、なりすましを防ぐのは FR-010 の署名だけ。
ADR 0004 の 10: 権限を有効にした台帳では各レコードに署名が付き、読み手が検証して通らないレコードを捨てて示す。鍵・署名の方式と依存は別の ADR。

いまの台帳（Issue #22 まで）は「誰でも編集モード」だけで動く。ジャーナルの行は `v1 … <CRC-32>` で、CRC-32 は壊れを見つけるが、なりすましは防がない（誰でも他人のアカウント ID で行を書ける）。

守る相手は「共有フォルダを読み書きできるが、台帳の編集者ではない人」と「編集者だが、他人の名で書こうとする人」。閲覧の制限は非要件（SPECIFICATION 第 3 節）。

鍵の方式の候補と、このリポジトリの制約（依存の許可制・ARC-013、`unsafe` は Windows の 2 クレートだけ・ADR 0002）:

| 候補 | 依存 | 評価 |
| --- | --- | --- |
| Ed25519（`ed25519-dalek` 2.x） | `ed25519-dalek` / `curve25519-dalek` / `ed25519` / `signature` / `sha2` / `digest` / `rand_core` ほか約 10 クレート。BSD-3-Clause（dalek）と MIT OR Apache-2.0 | 鍵 32 バイト・署名 64 バイト・決定的・`#![no_std]` で core に入れられる。実績が多い |
| ECDSA P-256（`p256`） | RustCrypto 約 12 クレート。MIT OR Apache-2.0 | 署名が非決定的（乱数が要る）で、同じ操作の再署名が別の行になる。Windows の CNG が持つが Linux に相当物が無く、OS に任せると 2 本になる |
| HMAC（台帳ごとの共有鍵） | `hmac` / `sha2` | 鍵を共有フォルダに置けば誰でも読めるので、なりすましを防げない。却下 |
| 自前の Ed25519 | 0 | 定数時間・副作用の無い実装を自分で保証できない。却下 |

## 決定（提案）

**権限を有効にした台帳では、ジャーナルを版 2（`journal/<account>.v2.log`）にし、各行に書き手の Ed25519 の署名を付ける。読み手は台帳の `keys/` にある公開鍵で検証し、通らない行は捨てて示す（FR-014）。権限は台帳の持ち主が署名した `permissions.v1.txt` で決める。**

1. **鍵。** アカウントの作成時に Ed25519 の鍵対を作り、秘密鍵は `account.v2.txt`（設定フォルダ・ADR 0008）に `secret = <64 桁>` で置く。公開鍵は台帳に参加するとき `keys/<account 16 進>.v1.pub`（`version = 1` / `id` / `name` / `public = <64 桁>`）として台帳のフォルダに**追記（新規作成）**する。既にあって中身が違えば示す（FR-014。同じアカウント ID の 2 台）
2. **行。** 版 2 の行は `v2 <時計> <アカウント> <壁時計> <打ち消す> <種類> <課題> [<項目> <値>] <署名 128 桁> <検査和>`。署名は「`v2` から値まで」をタブで結んだバイト列への Ed25519 署名。版 1 の読み手には `.v2.log` が「読めない版」として示される（ADR 0004 の 11）
3. **権限。** `permissions.v1.txt`: `version = 1` / `owner = <account>` / `editor = <account>` の行 / `group = <名前>: <account>, …` の行 / `signature = <owner の署名>`。`owner` は `docket.v1.txt` を作ったアカウントで、`docket.v1.txt` にも `owner = <account>` と `permissions = on` を足す（版は 1 のまま・鍵の追加は読み手が無視できる）。`editor` と `group` の全員が書ける。ファイルが無い台帳は今まで通り誰でも編集
4. **検証。** 読み手は行の署名を公開鍵で確かめ、書き手が `editor`（か `group` の中）であることを `permissions.v1.txt` で確かめる。どちらかが通らない行は捨て、アカウントと数を示す。自分の行も同じ規則で読む
5. **置き場。** 署名と検証の純関数は core（`#![no_std]`・`ed25519-dalek` の `no_std` の機能だけ）。鍵の生成は adapters（乱数）。ファイルは store
6. **依存。** `ed25519-dalek`（`default-features = false`・`alloc`）を core の唯一の外部クレートにする。CNF-013 の許可表と `deny.toml` の `allow` に BSD-3-Clause を足す（**ここが施主の判断**）。ADR 0002 の「core は依存 0」を改める

## 強制

- planned: CNF-013 の許可表に `ed25519-dalek` を core にだけ足し、他のクレートからの直接の依存を拒む
- planned: `deny.toml` の `allow` に `BSD-3-Clause`（実測して、本当に引くクレートだけ）
- planned: 版 2 の行の往復・改竄の検出・権限に無いアカウントの行の拒否を core と store のテストで。`make prove` に「署名の無い版 2 の行は読めない」を足す

## 結果

- 得られるもの: 編集者の名乗りが検証できる。権限を使わない台帳は何も変わらない（FR-003）
- 失うもの: core に外部クレートが入る。exe が 200〜300 KB 増える。行が 130 バイト増える（1 年分 45 MB → 約 85 MB・第 20 節の実測から）
- 残る穴: 秘密鍵は設定フォルダの平文（OS の利用者の権限で守る）。鍵の失効・交代の手続きは別の Issue。権限を有効にする・無効にするの切り替えは、持ち主が `docket.v1.txt` を書き換える（ジャーナルでないので追記でない）

## 却下した選択肢

上の表の HMAC と自前実装。加えて:

| 選択肢 | 却下の理由 |
| --- | --- |
| 署名を別ファイル（`journal/<account>.v1.sig`）に置く | 行と署名の対応がずれると検証できない。1 行に 1 署名で、壊れた末尾の扱い（ADR 0004 の 9）も同じ規則で済む |
| 権限をジャーナルの操作（op）にする | 権限の変更が併合の順序に依り、誰の操作を数えるかが循環する。権限は持ち主が署名した 1 つのファイルに固定する |
