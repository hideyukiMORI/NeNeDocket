# ADR 0010 — 権限を有効にした台帳では、操作の行に Ed25519 の署名を付け、読み手が公開鍵で検証する

- 状態: **受理**（施主 2026-10-21「後は推しで」・Issue #29 で実装）
- 日付: 2026-10-21（提案 Issue #25・受理と実装 Issue #29）
- Issue: #25 / #29
- 影響する規則: ARC-009 / ARC-010 / ARC-013 / RS-016 / QLT-010 / CNF-013。ADR 0004 の 10 を実装する

## 文脈

FR-010: 権限とグループを設定できる。設定しなければ誰でも編集できる。FR-009: アカウントはローカルの乱数の ID で、パスワードは無く、なりすましを防ぐのは FR-010 の署名だけ。
ADR 0004 の 10: 権限を有効にした台帳では各レコードに署名が付き、読み手が検証して通らないレコードを捨てて示す。鍵・署名の方式と依存は別の ADR。

Issue #22 までの台帳は「誰でも編集モード」だけで動く。ジャーナルの行は `v1 … <CRC-32>` で、CRC-32 は壊れを見つけるが、なりすましは防がない（誰でも他人のアカウント ID で行を書ける）。

守る相手は「共有フォルダを読み書きできるが、台帳の編集者ではない人」と「編集者だが、他人の名で書こうとする人」。閲覧の制限は非要件（SPECIFICATION 第 3 節）。

鍵の方式の候補と、このリポジトリの制約（依存の許可制・ARC-013、`unsafe` は Windows の 2 クレートだけ・ADR 0002）:

| 候補 | 依存 | 評価 |
| --- | --- | --- |
| Ed25519（`ed25519-dalek` 2.x） | `ed25519-dalek` / `curve25519-dalek` / `ed25519` / `signature` / `sha2` / `digest` / `subtle` ほか（実測 17 クレート・手続きマクロ含む）。BSD-3-Clause（dalek / subtle）と MIT OR Apache-2.0 | 鍵 32 バイト・署名 64 バイト・決定的・`#![no_std]` で core に入れられる。実績が多い |
| ECDSA P-256（`p256`） | RustCrypto 約 12 クレート。MIT OR Apache-2.0 | 署名が非決定的（乱数が要る）で、同じ操作の再署名が別の行になる。Windows の CNG が持つが Linux に相当物が無く、OS に任せると 2 本になる |
| HMAC（台帳ごとの共有鍵） | `hmac` / `sha2` | 鍵を共有フォルダに置けば誰でも読めるので、なりすましを防げない。却下 |
| 自前の Ed25519 | 0 | 定数時間・副作用の無い実装を自分で保証できない。却下 |

## 決定

**権限を有効にした台帳では、ジャーナルを版 2（`journal/<account>.v2.log`）にし、各行に書き手の Ed25519 の署名を付ける。読み手は台帳の `keys/` にある公開鍵で検証し、通らない行は捨てて数を示す（FR-014）。権限は台帳の持ち主が署名した `permissions.v1.txt` で決める。**

1. **鍵。** アカウントの作成時に Ed25519 の鍵対を作り、秘密鍵は `account.v2.txt`（設定フォルダ・ADR 0008）に `secret = <16 進 64 桁>` で置く。鍵の無い `account.v1.txt` は読んだとき鍵を足して版 2 に書き直す（版 1 は消さない・ARC-009）。公開鍵は台帳を開くたび `keys/<account 16 進>.v1.pub`（`version = 1` / `id` / `name` / `public = <16 進 64 桁>`）として台帳のフォルダに**無いときだけ**置く。権限を使わない台帳にも置く（履歴の「誰が」に名前を出す・FR-009）。既にあって鍵が違えば上書きせず示す（FR-014。同じアカウント ID の 2 台）
2. **行。** 版 2 の行は `v2 <時計> <アカウント> <壁時計> <打ち消す> <種類> <課題> [<項目> <値>] <署名 128 桁> <検査和>`。署名は「`v2` から値まで」をタブで結んだバイト列への Ed25519 署名。検査和は署名まで含めた CRC-32。版 1 の読み手（Issue #28 まで）には `.v2.log` が「ジャーナルでない名前」として失敗に出る（ADR 0004 の 11）
3. **権限。** `permissions.v1.txt`: `version = 1` / `owner = <account>` / `editor = <account>` の行 / `group = <名前>: <account>, …` の行 / `signature = <owner の署名>`。署名は `signature` より前の行をそのまま結んだバイト列への署名。`owner` は `docket.v1.txt` の `owner`（Issue #29 以降に作った台帳は作ったアカウント。それより前の台帳は、最初に権限を触ったアカウント）。`docket.v1.txt` には `owner = <account>` と `permissions = on|off` を足す（版は 1 のまま・知らない鍵は前の読み手が無視する）。持ち主と、`editor` と、どれかの `group` の中の全員が書ける。ファイルが無ければ持ち主だけ。`permissions = off`（か無い）台帳は今まで通り誰でも編集
4. **検証。** 読み手は行の署名を `keys/` の公開鍵で確かめ、行のアカウントがファイルのアカウントと同じで、書き手が書けることを `permissions.v1.txt` で確かめる。どれかが通らない行は捨て、数を示す。自分の行も同じ規則で読む（自分が編集者でなければ「編集者でない」と示し、追記はするが読み手（自分を含む）は捨てる）。権限を有効にした台帳では版 1 の行（権限より前の履歴）も「署名が無い」として捨てて数える。`keys/` と `permissions.v1.txt` は読み直しのたびに読み直すが、既に読み進めた行は開き直すまで読み直さない（権限を広げたら、広げられた人の前の行は次に開いたときに入る）
5. **置き場。** 署名と検証の純関数は core（`#![no_std]`・`ed25519-dalek` の `no_std` の機能だけ・`hex` / `SigningKey` / `PublicKey` / `Signature` / `Permissions`）。ファイルの形は application（`account_file` 版 2・`key_record`・`permissions_file`）、鍵の生成は adapters（乱数）、ファイルと検証器は store（`verifier` / `key_file` / `permissions_store` / `administration`）
6. **持ち主の操作。** 画面には無く、コマンドライン: `nene-docket <フォルダ> --permissions on|off` / `--allow <account>` / `--disallow <account>` / `--group <名前> <account>` / `--ungroup <名前> <account>`（複数可・順に当てる）。持ち主でなければ失敗し、何も書かない。成功すれば黙って終わる（RS-014）
7. **依存。** `ed25519-dalek`（`default-features = false`・`alloc` も無し）を core の唯一の外部クレートにする。CNF-013 の許可表に core だけ `ed25519-dalek` を書き、`deny.toml` の `allow` に実測の BSD-3-Clause（ed25519-dalek / curve25519-dalek / subtle）を足す。「core は依存 0」を「core の外部クレートは表に書いたものだけ」に改める（ARC-013 / ADR 0006 の注）

## 強制

- active: CNF-013 の許可表に `ed25519-dalek` を core にだけ置き、他のクレート（application / store / xtask）からの直接の依存を拒む（`cargo test -p xtask` の `cnf013_catches_external_crate_in_core_but_allows_the_listed_one`）
- active: `deny.toml` の `allow` に `BSD-3-Clause`（`make deny` の実測・gate-proofs 第 22 節）
- active: 版 2 の行の往復・改竄の検出・署名の無い版 2 の行の拒否・権限に無いアカウントの行の拒否・なりすましの拒否を core（`signing_key`）と store（`journal_record` / `verifier` / `other_journals` / `file_journal`）のテストで。`make prove` には足さない（prove は clippy / fmt / deny の発火の証明で、ここはふつうの単体テストの範囲）

## 結果

- 得られるもの: 編集者の名乗りが検証できる。権限を使わない台帳は何も変わらない（FR-003）。履歴の「誰が」に名前が出る（`keys/`）
- 失うもの: core に外部クレートが入る（実測 17 クレート・Windows の exe は 2.0 MB → 2.4 MB）。行が約 130 バイト増える（1 年分 45 MB → 約 85 MB・第 20 節の実測から）
- 残る穴: 秘密鍵は設定フォルダの平文（OS の利用者の権限で守る）。鍵の失効・交代の手続きは別の Issue。権限を有効にする前の履歴は、有効にすると捨てられる（無効に戻せば戻る）。権限を変えた後、既に読み進めた行は開き直すまで反映しない。権限を変える画面は無い（コマンドラインだけ）

## 却下した選択肢

上の表の HMAC と自前実装。加えて:

| 選択肢 | 却下の理由 |
| --- | --- |
| 署名を別ファイル（`journal/<account>.v1.sig`）に置く | 行と署名の対応がずれると検証できない。1 行に 1 署名で、壊れた末尾の扱い（ADR 0004 の 9）も同じ規則で済む |
| 権限をジャーナルの操作（op）にする | 権限の変更が併合の順序に依り、誰の操作を数えるかが循環する。権限は持ち主が署名した 1 つのファイルに固定する |
| 権限を有効にした台帳でも版 1 の行を読む | 署名の無い行を通せば、権限を有効にする意味が無い（誰でも版 1 の行を足せる） |
