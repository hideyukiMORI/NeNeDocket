# ADR 0023 — 自動の項目（起票日・起票者・完了日・更新日）は併合の派生値として課題に持ち、スナップショットを版 2・設定を版 7 に上げる

- 状態: **受理**（Issue #117・施主 2026-11-09「推しで」）
- 日付: 2026-11-09
- Issue: #117（#107 から切り出し）
- 影響する規則: ADR 0004（追記専用と併合）/ ADR 0015（スナップショット）/ FR-001 / FR-012（設定）/ FR-017 / QLT-008 / ARC-007 / ARC-009（移行）
- 番号について: 0021（カタログ先行の課題管理表・PR #108）と 0022（採用した見た目・PR #110）は未マージの PR が持っている

## 文脈

運用の筋書き（Issue #115・[docs/design/2026-11-09-operating-scenario.md](../design/2026-11-09-operating-scenario.md)）の 1 段「足す」と 5 段「閉じる」で、起票日・起票者・完了日が自動で入ることが Excel の課題管理表から乗り換える人の前提になっている。方針（PR #108）の段階 0 は「データの形を変えずに」導くとしていたが、#107 の前半で次が分かった。

- 値は操作の壁時計から決まるので、併合の時点で課題に刻めば正しく、表示のたびにジャーナルを引く必要が無い。ただし課題に値を足すと、課題を丸ごと持つスナップショット（ADR 0015）の形が変わる
- 表の列を足すと、設定の版 4〜6 の `order`（6 列ちょうど）と `columns`（5 つの幅）が読めなくなり、**既存の利用者が起動できなくなる**（読めない設定は起動を止めて示す・FR-014）

## 決定

1. **`Item` に `opened` / `updated` / `closed` を持つ。** `Item::applied(&Op)` が刻む唯一の経路（`Docket::applied`・課題の作り直し・履歴の再現が同じ関数を通る・ARC-001）。
   - 起票日: 作る操作の壁時計
   - 更新日: 全順序で最後にその課題に当たった操作の壁時計（権限の記録は当たらない）
   - 完了日: 完了でない状態から完了へ移した、全順序で最後の操作の壁時計。完了から外せば消える。完了のまま完了を置いても変わらない
   - 起票者は新しく持たない（`ItemId::creator`）。表では番号と同じ略称（Issue #107）
   - 新しい操作の種類は足さない。ジャーナルの形と版は変えない
2. **スナップショットを版 2 にする。** `item` の行の末尾に `<起票日> <更新日> <完了日|->`（Unix 秒）。ファイル名も `snapshot/<account>.v2.txt` / `.v2.idx`。版 1 は読まず、開いたときに自分の版 1 のファイル（と一時名）を捨てる（300 万操作で 100 MB を超える置き去りを作らない）。派生値なので、新しい実行ファイルの最初の起動で 1 度だけ全部読み直す
3. **設定を版 7 にする。** 列は 10（番号・題名・状態・担当・期限・ラベル・起票日・完了日・起票者・更新日）。`columns` は題名以外の 9 つの幅、`order` は**出している列を左から**（題名は必ず・残りは後ろに控える）。版 6 までの `columns`（5 つ）は足した 4 列を既定の幅で補い、`order`（6 列）には起票日と完了日を右に足す。書くのは版 7 だけ
4. **既定で出すのは起票日と完了日**（起票者と更新日は控える）。出し入れの画面は見た目の第 1 段（運用の筋書きの B）で入れる。それまでは設定の `order` を書き換えれば出せる
5. 日付は表示の機械の地方時の `YYYY-MM-DD`（`WallClock::date_at`・時差はアダプタ・ARC-007）

## 帰結

- 得たもの: 定例で「いつ起票され、いつ閉じたか」が表で読める。値は併合の派生値なので、同じ操作の集合を別の順で読んでも同じ（QLT-008 のテストは課題を丸ごと比べる）
- 失ったもの: 古い実行ファイルは版 7 の設定を読めない（同じ機械で新旧を混ぜない）。古い実行ファイルは版 2 のスナップショットを見ず、自分の版 1 も新しい実行ファイルが消しているので、全部読み直す（正しさは変わらない）
- 壁時計がずれた機械の操作は、ずれたままの日付で出る（並びは論理時計のまま・ADR 0004）。`merge` の時計のずれのテストは「値と順は変わらず、自動の日付だけが壁時計に従う」に改めた
- 並べ替えはしない（段階 1）。CSV から取り込んだ起票日・完了日を優先する規則は取り込み（筋書きの E）で決める

## 検討した案

| 案 | 却下の理由 |
| --- | --- |
| 表示のたびに課題ごとの操作をジャーナルから引く（データの形を変えない） | 見えている行の数だけ毎フレーム索引を読む（スクロールのたびに数 ms）。並べ替え・絞り込みに使えない |
| スナップショットの版は 1 のまま形だけ変える | 新旧の実行ファイルが互いのファイルを「壊れている」と捨て合う。版で分けるほうが素直 |
| 設定の `order` を 10 列ちょうどにし、出し入れは別の鍵 | 鍵が 2 つで 1 つの意味（列の見え方）を持つ。出している列の並びだけを持てば足りる |
