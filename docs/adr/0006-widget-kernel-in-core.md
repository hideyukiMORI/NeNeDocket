# ADR 0006 — 部品の核は即時モードで core に置く。既製の部品ライブラリは入れない

- 状態: 受理
- 日付: 2026-10-21
- Issue: #4
- 影響する規則: ARC-003 / ARC-004 / ARC-007 / ARC-011 / ARC-013 / RS-001 / RS-002 / QLT-008 / QLT-009

## 文脈

施主の問い（2026-10-21）: 「フォーム系コンポーネントの最低限だけ、Windows と Linux で見た目がほぼ同じになり、使い勝手もほぼ同じで、軽くて速いものはあるか」。
候補を比較した。

| 候補 | 見た目の同一性 | IME | 軽さ | 代償 |
| --- | --- | --- | --- | --- |
| egui（Rust） | 自前描画で同じ | winit 経由で通る | 速い | wgpu か OpenGL が要る。依存 150〜250 クレート。画素を OS 無しでテストできない |
| FLTK（fltk-rs） | 自前描画で同じ（1990 年代風） | XIM / IMM32 を内蔵 | 1〜2 MB・GPU 不要 | C++ をビルドする。Rust の lint も `no_std` も xtask も C++ 側には届かない |
| Slint | 同じ。ソフトウェアレンダラあり | 部分的 | 軽い | 独自言語。GPLv3 か royalty-free 契約で、deny.toml の許可制と相談になる |
| microui / Nuklear 系（即時モードの核だけ） | 描くのは自分 | 無い | 依存 0 | 「自作」の設計図を借りるだけ |
| iced / Dear ImGui / Xilem | 同じ | まちまち | 中〜重 | egui より依存が多いか、成熟が足りない |

施主は「部品の核は microui の設計を借りて core に書く。既製品は入れない」で決めた（ADR 0002 を保つ）。
決め手は、既製品のどれも ADR 0002 の却下理由（依存の木・GPU の描画・画素を OS 無しでテストできない・C++ の領域）を引き受けることになり、
そのうち「2 OS で同じ見た目と手応え」は自前描画でも配置と当たり判定を core に置けば得られる、という点。既製品が本当に肩代わりしてくれるのは IME だけである。

## 決定

**部品の核は即時モード（microui の形）で core に置く。UI は毎フレーム入力を渡し、矩形と ID で部品を問い合わせ、描画命令の列を描くだけ。**

1. **状態の持ち主は 1 つ。** `Interaction` がフレームをまたぐ状態（押している部品・フォーカスの持ち主）を持つ。`begin(入力)` → 部品ごとに `probe(ID, 矩形, フォーカス可)` → `end()`。`probe` の順が Tab の順
2. **部品は関数。** `button` / `checkbox` / `text_field` / `select_box` / `scroll_bar` は、矩形と状態と判定から `DrawCommand` の列を返す純関数。部品の種類は閉じた集合ではなく、関数を足せば増える
3. **配置も純関数。** `Layout`（段を上から積み、列に割る）と `TableLayout`（ヘッダ・行・列。見えている行だけを計算する）。1 万件の表で全行を舐めない（FR-002）
4. **編集状態は値。** `TextEdit`（文字列・カーソル・選択・確定前の文字列）は鍵の意図を適用して新しい値を返す。位置は文字の添字で、バイトでは持たない。`SelectState` と `ScrollState` も同じ
5. **文字の幅は core で測らない。** `DrawCommand::Text` はカーソルを文字の添字で持ち、UI がフォントで画素の位置に直す。core に依存が入らず、`#![no_std]` を保つ
6. **色は意味で渡す。** `Paint`（地・面・縁・文字・強調・選択）を UI が見え（ダーク・ライト）から色に直す。2 OS で同じ命令、同じ色
7. **IME は UI の仕事。** 確定前の文字列は `Preedit` として `TextEdit::with_preedit` で core に入り、確定は `inserted`。XIM / TSF の扱いは X11 の窓を出してから実測して別の ADR

## 強制

- **active**: 配置・判定・編集状態が OS 無しで動くことは、core が `#![no_std]`（CNF-007）で依存 0（CNF-013）であることが構造で守る。決定性は ARC-007（CNF-012）。Issue #4 で実ファイルの発火を記録した（gate-proofs 第 9 節）
- **不能**: 「UI に業務の判断を置いていないか」「部品の関数に状態を持ち込んでいないか」はレビュー事項（ARC-011）

## 結果

得られるもの:

- 依存 0 のまま、部品の見た目と手応えが 2 OS で同じになる（配置と判定が同じ関数）
- 部品の核のテストが OS 無しで走り、region カバレッジ 99.71%（Issue #4 の実測）
- 1 万件の表の配置が 1 フレームに収まる根拠が、見えている行だけを計算する `TableLayout::visible_rows` の形で書ける

失うもの・残る穴（**正直に**）:

- 🔴 **IME は丸ごと残る。** egui なら winit が肩代わりしてくれた分。XIM と TSF の重さは別の ADR で実測するまで分からない
- 🔴 **アクセシビリティは無い**（ADR 0002 と同じ）
- 即時モードは毎フレーム全部品を問い合わせる。1 万件の表は見えている行だけ問い合わせるので問題ないが、部品が数千になる画面は作らない前提
- 文字の幅を core が知らないので、「文字が収まるか」の判断は UI に残る。収まらないときの切り詰めは UI の仕事
- 部品の見た目は最小（面・縁・文字）。影・角丸・アニメーションは無い。施主の好みで足すなら `DrawCommand` に種類を足す

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| egui を入れる | 依存 150〜250 クレートと GPU の描画。ADR 0002 の却下理由をそのまま引き受ける。得られるのは IME の肩代わりだけで、それは別の ADR で自前に書く |
| FLTK を入れる | 軽くて速くて安定だが、C++ が入ると xtask の規約検査も lint も `no_std` も届かない領域ができる。ポリシーの外に部品が出る |
| Slint を入れる | ライセンスが許可制（ARC-013）と噛み合わない。独自言語が第 2 の経路になる |
| 保持モード（部品の木を持つ）で自作する | 状態の持ち主が部品ごとに散り、ARC-004 の表に載らない状態が増える。即時モードなら持ち主は `Interaction` 1 つ |
| microui を C のまま FFI で呼ぶ | `unsafe` と C のビルドが入る。1,100 行なら Rust で書くほうが小さい |
| 文字の幅を core で測る（フォントの計測を core に） | フォントのラスタライザか計測表が core に入り、依存 0 と `no_std` が壊れる |
