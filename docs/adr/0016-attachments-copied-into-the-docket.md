# ADR 0016 — 添付は台帳フォルダに写し、ジャーナルに `attach` / `detach` を追記する

- 状態: **受理**（施主 2026-10-21「ファイル添付にも対応したい」→ 8 点の提案に「全部推しで」・Issue #62）
- 日付: 2026-10-21
- Issue: #62（記録と段・`--attach`）。ビューワーは #63 / #64 / #66、ドラッグ＆ドロップは #65
- 影響する規則: FR-021 / FR-022 / ADR 0004 の 1（台帳フォルダに置くもの）/ ARC-013（依存は許可制）

## 文脈

施主は課題にファイルを添付したい。台帳は共有フォルダ（SMB）の上の追記専用ジャーナル（ADR 0004）で、各プロセスは自分のアカウントのジャーナル 1 本だけを書く。添付の中身はジャーナルに入れたくない（1 行 1 操作・テキスト・読み直しは伸びた分だけ）。元のファイルは利用者の手元にあり、他の参加者から見える場所とは限らない。

## 決定

**添付は台帳フォルダの `attachments/` に写し、ジャーナルには写しの名前・大きさ・SHA-256 を `attach` の行で追記する。外すのは `detach` の追記で、写しは消さない。**

1. **置き場。** `attachments/<作ったアカウント 16 進>-<課題の連番>/<添付の連番>-<安全な名前>`（当初は `:` で区切っていたが Windows / SMB で作れないので Issue #74 で `-` に直した。名前は core の `safe_name` で `< > : " / \ | ? *`・制御文字を `_` に、予約名に `_` を前置、120 バイトに収める。記録の `name` は元のまま）。課題ごとのフォルダ、添付の連番は課題ごとに 1 から（`Item::last_attachment` の次・外しても戻しても増える）。同じ名前を 2 度添付しても連番で別の写しになる。元のファイルは触らない。写しは一時名に書いて rename する（読みかけの他プロセスに半端な写しを見せない）
2. **記録の形。** `attach <課題> <連番> <バイト数> <SHA-256 の 16 進 64 桁> <名前>`（名前はタイトルと同じ逃がし方）と `detach <課題> <連番>`。版は 1・2 のまま（権限が有効なら署名付き）。併合では `Item::attachments` の列を足す・外す。Undo は `Attach` ↔ `Detach` の逆の操作を足す（ADR 0004 の 4・`Detach` の逆はその課題の操作から `attach` の行を引く）。履歴には「添付した: 名前」「添付を外した: 名前」、`--audit` にも同じ行が出る（ADR 0014）
3. **中身の印。** SHA-256 は core に自分で書く（FIPS 180-4・既知の値のテスト）。外部クレートは足さない（ARC-013・`sha2` を足せば `digest` 系が連れて来られる）。写しを読み直して記録と合わなければ、添付の段の名前に `⚠` と「中身が記録と合いません」を添える（黙って出さない・FR-014）。合わせ直す経路は作らない（添付し直せば新しい連番）
4. **入力。** 添付の段（道具の段の「添付」のチェック・選んだ課題の下）のパスの欄に打って Enter か「添付する」、またはコマンドライン `nene-docket <フォルダ> --attach <作ったアカウント 16 進>:<連番> <パス>`（画面は開かない・権限は同じ）。ドラッグ＆ドロップは Issue #65 で足す（X の XDND・Windows の `WM_DROPFILES`）
5. **スナップショット（ADR 0015）。** 課題の行に添付の列（`連番:バイト数:SHA-256:名前` を `,` 区切り）と最後の連番を足す。Issue #61 のスナップショット（列が無い）は形が読めないので捨てて全部読む（ADR 0015 の 3 の経路・1 度だけ）
6. **写しは消さない。** 外した添付も、他人が見られるように写しは残る（追記専用と同じ理由・ADR 0004 の 3）。フォルダの肥大は残る穴（整理は別の Issue）

## 強制

- active: `attach` / `detach` の行の往復と壊れた行の拒否（store `journal_record`）、写し・SHA-256・改変の検出（store `attachment_store`）、`Attach` ↔ `Detach` の逆の操作（core `merge`）、添付の列を持つスナップショットの往復（store `snapshot_file`）、画面の段から添付・外す・Undo・読めない元のファイルの知らせ・改変の印（application `docket_screen`）、`--attach` の引数（app `arguments`）。既知の値の SHA-256（core `sha256`）。Issue #62・gate-proofs 第 39 節
- 不能: 共有フォルダを直接書ける人は写しを差し替えられる。印は読んだ人にだけ出る（署名は `attach` の行で、写しそのものには付かない）

## 結果

- 得られるもの: 添付が他の参加者に数秒で届く（ジャーナルの読み直しと同じ経路）。改変が分かる。依存が増えない
- 失うもの: 台帳フォルダが写しの分だけ大きくなり、消す経路が無い。元のファイルが更新されても写しは古いまま（添付し直す）
- 残る穴: 大きなファイルは丸ごと記憶に読んで写す（SHA-256 のため）。名前は元のファイル名だけで、重複は連番で区別する。パスは手で打つ（#65 まで）。中身を見る手段はまだ（#63 / #64 / #66）
