# ADR 0012 — 配色は nene-nib の組み込み 125 テーマを写し、台帳の 8 色は本文の 3 色から整数の補間で導く。希望は設定に残し `system` は OS の明暗に従う

- 状態: 受理
- 日付: 2026-10-21
- Issue: #27
- 影響する規則: ARC-001 / ARC-004 / ARC-007 / ARC-009 / ARC-011 / RS-007 / RS-016 / QLT-008 / QLT-009 / QLT-013。FR-012 の「見え」

## 文脈

施主の依頼（2026-10-21）: 「NeNeNib と同様にテーマを選べるようにしたい」。nene-nib は組み込み 125 配色（Vim 標準・IDE の定番・MonaLisa・映画着想の独自 37 種）を `Theme{name, appearance, ui, body, source}` の値型で持ち、有名テーマの UI トークンは本文の 3 色から整数の補間 `derive_ui` で導く（nene-nib ADR 0017 / 0117、`docs/design/2026-10-12-colorschemes.md`）。

Docket の色の役割は 8 つ（`Paint`: 背景・面・縁・字・控えめ・強調・強調の上・選択）で、Issue #22 までは core の `palette::light` の 1 表だけだった。Nib のような本文のハイライトは無い。

制約: core は浮動小数の libm に頼らない（整数だけ）、乱数も時刻も読まない（ARC-007）。色の値そのものは著作物ではないが、名前と出典は残す。

## 決定

**配色の元は `ThemeSeed`（名前・明暗・背景・前景・強調・作者・許諾・出典）の表 `theme_catalog::SEEDS` で、nene-nib の 125 配色を順も値もそのまま写す。台帳の 8 色は `theme_derivation::derive` が明暗ごとの百分率の表 1 つで導く。希望は `ThemeChoice`（`system` か名前）として設定の版 2 に残し、`system` は起動時に観測した OS の明暗の既定（ダーク `ubuntu-aubergine`・ライト `neutral-light`）にする。**

1. **表**: `docs/design/colorschemes.md` と同じ 125 行。名前は小文字とハイフン（`_` は `-` と同じに受ける）。出典の URL はアプリが読みに行かない
2. **導出**（sRGB の値のまま線形補間 `mix(from, to, percent)`。ガンマは扱わない）:

   | 役割 | 計算 | ダーク | ライト |
   | --- | --- | --- | --- |
   | 背景 / 字 / 強調 | そのまま | | |
   | 面 | 背景 → 字へ／背景 → 白へ | 6% | 100%（白） |
   | 縁 | 背景 → 字へ | 22% | 15% |
   | 控えめ | 字 → 背景へ | 30% | 30% |
   | 選択 | 背景 → 強調へ | 28% | 22% |
   | 強調の上 | 強調の明るさ `(299R + 587G + 114B) / 1000` が 160 以上なら黒、未満なら白 | | |

   百分率は Nib の `derive_ui` から Docket の役割に写したもので、**見た目は仮**。施主が見て変えるなら表の数字だけを変える
3. **コントラスト**: 125 配色すべてで字 / 背景が 4.5 以上、字 / 面が 4.0 以上であることを core のテストが要求する（WCAG 2 の相対輝度。浮動小数はテスト側だけ）。Nib が本文の前景 / 背景で 4.5 を保証しているので、同じ 2 色を使う Docket も通る
4. **希望と表示の分離**: 設定の `theme = system|<name>`。`system` は OS の明暗（Windows はレジストリの `AppsUseLightTheme`、X11 は標準が無いので分からない＝ライト）の既定。起動後の OS の変更には追従しない。知らない名前の設定は読めない設定として起動を止める（FR-014）
5. **切り替え**: 道具の段の欄に名前を打って Enter（`system` も）、欄にフォーカスがあれば上下で表を巡る（即座に見えが変わり設定に書く）。知らない名前は変えずに通知。セレクトボックスにしないのは 126 の候補が窓に収まらないため（候補の列にスクロールが無い）
6. **フレームが配色を運ぶ**: `DocketFrame` が解決した `Theme` を持ち、UI は `theme.palette().colour(paint)` で色にする。UI に色のリテラルは無い（ARC-011。X11 の cairo と Windows の Direct2D が同じ表を読む）
7. **利用者のテーマファイル**（Nib の `.v1.theme`）は入れない。別の Issue

## 強制

- active: 全配色のコントラストと名前の一意性のテスト（core）。`ThemeChoice::from_keyword` の往復
- active: core は整数だけ（`as` 禁止・`u32::from` と `u8::try_from`）。`derive` は決定的
- active: 設定の版 2（ADR 0011 の 7）
- planned: UI に色のリテラルを書かない字句検査（CNF）

## 結果

- 得たもの: 125 配色が X11 と Windows で同じ表から出る。Xvfb で `dracula`・`one-dark`・`solarized-light` に切り替わった（gate-proofs 第 21 節）
- 失うもの: 既定のライトの見えが変わった（Issue #5〜#20 の `palette::light` の青い強調から、Nib の `neutral-light` の橙の強調へ）。元の配色に戻すなら表に 1 行足す
- 残る穴: X11 で OS の明暗を観測できない（`system` は常にライト。GNOME の `color-scheme` などは別の Issue）。導出の百分率は施主の目を通していない。Nib の本文 16 色（構文の役割）は写していない（Docket に本文のハイライトが無い）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 8 色を 125 配色ぶん手で書く | 1,000 個の値を目で決められない。Nib と同じく 3 色から導き、必要な配色だけ後で上書きする |
| 明暗 2 つだけ（ライト・ダーク） | 施主が Nib と同様の選択を求めた。表を写すだけなので費用は小さい |
| 配色を設定ファイルでなく台帳に置く | 見えは利用者のもので、台帳を共有する人ごとに違う（FR-012） |
| OS の明暗の変化に追従する | 起動時の観測で足りる。追従は UI が時間と OS を読む経路になる（ARC-007）。設定で明示すれば変わらない |
