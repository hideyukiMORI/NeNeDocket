# ADR 0014 — 権限の変更もジャーナルに追記し、台帳全体の時系列を監査として出す

- 状態: **受理**（施主 2026-10-21「監査のために誰が何をしたか全てログを残すようにしたい」・Issue #56 で実装）
- 日付: 2026-10-21
- Issue: #56
- 影響する規則: ARC-009 / FR-006 / FR-010 / FR-014。ADR 0004（ジャーナル）・ADR 0010（署名）・ADR 0013（引き継ぎ・持ち主の交代）

## 文脈

課題の編集は、アカウントごとの追記専用ジャーナル（ADR 0004）に 1 行 1 操作で残る。誰が（アカウント・`keys/` の名前）・いつ（壁時計）・何をしたか（操作）が書かれ、権限を有効にした台帳では署名が付く（ADR 0010）。消しても「消した」が残る。この部分は既に監査の記録である。

残っていなかったのは権限の変更（有効・無効、編集者、グループ、引き継ぎ、持ち主の交代）。`permissions.v1.txt` は署名した現在の状態を上書きするので、誰がいつ誰を編集者にしたかは消える。

施主の求めは「誰が何をしたか全てログを残す」。

## 決定

**権限の変更も操作としてジャーナルに追記する（`OpKind::Admin(AdminCommand)`）。併合は無視し（台帳の状態は変えない）、履歴にだけ出る。画面では履歴の段で課題を選んでいないときに台帳全体の時系列（課題の編集 ＋ 権限の変更）を出し、`nene-docket <フォルダ> --audit` で同じ時系列をテキストで標準出力に出す。**

1. **記録の形。** `AdminCommand` は core に置き、`OpKind::Admin` が持つ。ジャーナルの行は種類 `admin`・課題 `-`・`<命令> <引数>…`（`permissions on|off` / `allow <id>` / `disallow <id>` / `group <名前> <id>` / `ungroup <名前> <id>` / `succeed <新> <旧>` / `owner <id>`）。版は 1・2 のまま（権限が有効なら署名付き）。画面（参加者の段）も合成ルート（コマンドライン）も、`permissions.v1.txt` を書いた後に application の `administration_log::record` を通る（同じ経路・ARC-001）
2. **併合と Undo。** `Docket::applied` は `Admin` で何もしない。`merge::inverse_of` は `None`（戻せない）で、Undo の束にも積まない。同じ操作の集合を別の順で読んでも同じ台帳（QLT-008）はそのまま
3. **見せ方。** 履歴の段は、課題を選んでいなければ `HistoryLine::all`（全操作の全順序・新しいものが先・課題の操作は番号を頭に・権限の記録は相手を `keys/` の名前で）。選んでいればこれまで通りその課題の履歴。`--audit` は古い順に `<いつ UTC>\t<誰が>\t<何を>` を 1 行 1 操作で出す（言語は設定の表示言語）
4. **読んだ記録は残さない。** 共有フォルダを直接読む人は何も残さないので、「開いた記録」は監査として信用できない。無いほうが誤解がない
5. **古い読み手。** `admin` の行を知らない読み手（Issue #56 より前）は壊れた行として数える（起動は止まらない）。読み手を先に更新する

## 強制

- active: `admin` の行の往復と、壊れた行の拒否（store `journal_record`）。`Admin` が台帳を変えず・戻せず・順に依らないテスト（core `merge`）。画面の権限の変更がジャーナルに記録され履歴に名前で出るテスト（application `docket_screen`）。`--audit` の形のテスト（application `audit_report`）。Issue #56・gate-proofs 第 36 節
- active: `AdminCommand` の正典は core の 1 つ（application の写しは消した。CNF-003）
- 不能: 記録の信頼は署名の範囲。権限を有効にする前の行（版 1）は署名が無く、有効にした後は捨てて数える（ADR 0010）。編集者が `admin` の行を書くことはできるが、署名で書いた本人が分かり、`permissions.v1.txt` の正本は持ち主の署名でしか変わらない

## 結果

- 得られるもの: 課題の編集と権限の変更の両方が、誰が・いつ・何を、の形で同じジャーナルに残り、画面でもテキストでも読める
- 失うもの: `OpKind::item()` が `Option` になり、読み手は権限の記録を課題と区別する
- 残る穴: 読んだ記録は無い（4）。権限の記録はジャーナルの持ち主の「言い分」で、読み手は `permissions.v1.txt` と突き合わせない

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 権限の変更を別のファイル（`audit.v1.log`）に追記する | 誰が・いつ・署名の仕組みを 2 つ持つことになる。ジャーナルの行に乗せれば署名も時計も読み直しも既にある |
| `permissions.v1.txt` の版を上げて履歴を中に持つ | 署名する文が伸び続け、読み手が毎回全部を検証する。現在の状態と履歴は分けるのが ADR 0004 の形 |
| 開いた（読んだ）記録も残す | 共有フォルダを直接読む人は残さないので、記録が「全部」に見えて全部でない。誤解を生む記録は持たない |
| 画面に「監査」の段を別に足す | 道具の段は既に 9 列。履歴の段の「課題を選んでいないとき」が空いていた |
