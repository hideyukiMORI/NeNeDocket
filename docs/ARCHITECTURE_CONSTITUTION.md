## 0. この文書の読み方

**すべての規則は「機械強制」の状態を持つ。**

| 表記 | 意味 |
| --- | --- |
| **active** | 違反すると `make check` の該当 target が落ちる。人の記憶に依存しない |
| **planned** | 規範だが、まだ機械が見ていない。**この行に触れる変更は PR で明示的に自己レビューすること** |
| **不能** | 言語・道具の仕様上、機械では塞げない。塞げないことを明記して残す |
| **不採用** | 検討して採らなかった。理由を必ず併記する（再提案は同じ理由への反論から始める） |

🔴 **planned を active と書き換えないこと。** 未実装の強制を実装済みに見せるのは、
規約全体の信頼を壊す唯一の行為である。実装してから書き換える。
どの規則がいまどの状態かの正本は [QUALITY_GATES.md](QUALITY_GATES.md) の強制マトリクスであり、
文書整合検査（CNF-009）が「本書に定義があるのにマトリクスに行が無い」「active に証明行が無い」を拒否する。

🔴 Issue #2 で機械を置き、このリポジトリの道具で発火を実測した規則だけを active にした（`make prove`・[gate-proofs](quality/gate-proofs.md)・[ADR 0005](adr/0005-rust-foundation-and-measured-limits.md)）。
Issue #4 で `crates/core` が生まれ、中核の実ファイルで CNF-007 / CNF-012 / CNF-013 を発火させた（gate-proofs 第 9 節）。

### 強制の責務を分ける

| 層 | 実体 | 守るもの |
| --- | --- | --- |
| コンパイラ / cargo | 型・可視性・網羅性・クレート境界・依存の非循環 | **不正な状態を「書けなく」する** |
| lint | `Cargo.toml` の `[workspace.lints]` ＋ `clippy.toml` | 書けてしまうが書くべきでないこと。抑制は二段構え（RS-019） |
| 規約検査 | `xtask`（依存ゼロ） | **NeNe Docket として守るべきこと**（CNF-NNN） |
| 依存の許可制 | `deny.toml`（cargo-deny）＋ `Cargo.lock` ＋ `--locked` | ライセンス・重複版・取得元・再現性 |

道具が重なっても責務は重ねない。同じ規則を 2 か所で設定すると、片方を緩めても誰も気づかなくなる。

### Rust がどこまで届いたか

先行事例（NeNe Loupe / NeNe Folio / NeNe Nib＝C++23 と C23、xi-tools と nene-ruler＝Rust）の比較。
**本リポジトリの列は Issue #2 の実測結果（rustc 1.98.0）。** 再現手順は `make prove`、記録は [gate-proofs](quality/gate-proofs.md) と [ADR 0005](adr/0005-rust-foundation-and-measured-limits.md)。nene-ruler と同じ出力が出た。

| 規則 | C++ / C（clang-cl・MSVC の実測） | **Rust（本リポジトリの実測）** |
| --- | --- | --- |
| 不正状態を表現不能に・網羅性 | 不十分。警告の明示指定で分岐漏れを拒否。`pragma` で迂回できる | **ある**（E0004。`_` は `wildcard_enum_match_arm` が forbid） |
| 公開状態は不変 | 不十分。公開 aggregate は lint も漏れる | **ある**（`let` が既定で不変。可変性が型に出る） |
| `null` の意味は一つ | 不十分。`nullptr` は通る | **ある**（`null` が無い。未初期化は E0381） |
| 非公開コンストラクタ＋唯一のファクトリ | ある（private）。検証済み値のコピーは可 | **ある**（E0603。`Default` だけが穴で、CNF-001 が塞ぐ） |
| 決定性（時刻・乱数・環境を読ませない） | 言語では無い。字句検査で一部を補う | **構造で守れる**（中核は `#![no_std]`。字句検査 CNF-012 が補う） |
| 依存方向は物理的 | CMake のグラフ検査で補う | **ある**（`[dependencies]` が import 可能な物の全リスト。循環は cargo が拒む） |
| 抑制は例外であって道具ではない | 言語では無い。waiver 台帳で補う | **より強い**（forbid 層は抑制不能・deny 層の `#[expect]` は腐らない） |

🔴 **穴が残ることを書かずに厳格さを主張しない。** 塞げなかったものは第 1 節と [CODING_RULES.md](CODING_RULES.md) 第 7 節に「不能」として残す。

## 1. 憲章規則

### ARC-001 — 一つの意味に一つの正典経路

一つの意味には、正典となる型・所有者・振る舞いの経路が **ちょうど 1 つ**存在する。
並行するサービス、同義の別モデル、アダプタ固有の業務ロジック、同じ概念の別名を作らない。
置き換えが必要なら、呼び出し側の移行と旧経路の削除を**同じ変更で**行う。

NeNe Docket で特に守る経路: 課題の状態は**ジャーナルの併合からだけ**作る。UI が持つ表示用の複製を正本にしない。
Undo はジャーナルを書き換えず、逆の操作を追記する（ADR 0004）。

- 機械強制: **planned**（レビュー事項。「意味が同じか」は機械が判定できない）
- 補助: CNF-004（総称名の禁止）と `clippy::pub_use`（再エクスポートの禁止）が「役割の分からない第 2 経路」の温床を減らす

### ARC-002 — 依存方向は物理的である

依存は [PROJECT_LAYOUT.md](PROJECT_LAYOUT.md) のグラフに従う。禁じた依存は「レビューで気をつけること」ではなく
**`use` できないこと**でなければならない。循環は許さない。

🔑 Rust では各クレートの `[dependencies]` が**そのまま import 可能なものの全リスト**であり、
循環は cargo が拒否する。向きの表との照合は CNF-013 が行う。

- 機械強制: **active**（cargo の循環拒否 ＋ CNF-013 の許可表。実測は P-23 と [gate-proofs](quality/gate-proofs.md) 第 8 節）

### ARC-003 — 中核はプラットフォームから独立している

中核（core / application）は X11・Win32・cairo・Direct2D・ファイル・ネットワーク・現在時刻・乱数・既定ロケール・環境変数を知らない。
プラットフォームは**型のあるポート**から入る。

🔑 中核クレートは `#![no_std]` ＋ `extern crate alloc` で書く。`std::fs` / `std::env` / `std::time` が
lint 違反ではなく**名前解決エラー**になる。宣言そのものが消えていないことは CNF-007 が見る。

- 機械強制: **active**（`#![no_std]` の宣言＝CNF-007、外部 crate の禁止＝CNF-013。Issue #4 で `crates/core/src/lib.rs` の `#![no_std]` を外して CNF-007 を、`std::time` を書いて E0433 と CNF-012 を、`regex` を足して CNF-013 を実ファイルで発火させた。[gate-proofs](quality/gate-proofs.md) 第 9 節）

### ARC-004 — 状態には唯一の所有者がいる

| 状態 | 意味 | 所有者 | 変更経路 |
| --- | --- | --- | --- |
| 台帳の状態 | 全アカウントのジャーナルを併合した、いまの課題の集合 | application | 自分の操作の追記と、他人のジャーナルの読み直し（`JournalPort`） |
| 自分のジャーナル | 自分のアカウントが書いた操作の列。追記のみ | store（ファイル）/ application（未同期の尾） | 操作の意図 → 追記 → 同期 |
| Undo の束 | 自分の操作のうち、まだ戻していないものと戻したもの | application | Undo / Redo の意図。実体はジャーナルから再構成できる |
| 編集状態 | いま開いている入力欄の文字列・カーソル・選択・直前の拒否 | application の `EditSession` | 鍵と IME の意図。確定で操作になる |
| 表の見え | 列の幅と順・ソート・絞り込み・スクロール位置 | application | 表の操作の意図。設定として保存する（FR-012） |
| アカウント | 自分の ID・名前・鍵 | application（起動時に一度取り込む） | `IdentityPort` の結果 |
| 環境 | UI の倍率・論理画素の比 | application | 起動時と `DpiChanged` の意図 |

同じ事実を 2 つの区分に独立して持たない。派生値（表示文字列・表の行・履歴の一覧）は再計算する。

- 機械強制: **planned**

### ARC-005 — 可変性は隔離区画にのみ存在する

外から見える core / application の状態は不変とする。可変な状態を持ってよいのは次の区画だけである。

| 区画 | 何が可変か | なぜ必要か |
| --- | --- | --- |
| application の状態遷移 | 所有する現在状態を不変の次状態へ置き換える | 操作の反映。公開値は不変 |
| ui-x11 / ui-win32 | 窓・描画面・部品の見た目の状態（ホバー・フォーカス） | 画面への反映。業務状態は複製しない |
| adapters-x11 / adapters-windows | クリップボード・時計・乱数・IME の OS 資源 | OS との入出力。取得値を検証済み値へ変換する |
| store | ジャーナルと設定ファイルのハンドル・読み出し位置 | ファイルとの入出力。版と形式をここに閉じる |

🔴 **区画を増やさない。** 必要になったら、この表と ADR を先に変える。

- 機械強制: **planned**

### ARC-006 — 合成は明示的である

依存は合成ルート（`crates/app` の `main`）で与える。サービスロケータ・遅延グローバル（`OnceLock` / `LazyLock`）・
暗黙のシングルトンを使わない。DI フレームワークを入れるには ADR が要る。

合成ルートは**プロセスそのものの責務**も持つ。端末への出力・コマンドライン引数・プロセスの終了コードを扱ってよいのは
合成ルートだけである。出してよいのは**起動できなかった理由 1 行**だけで、ログの手段として使わない。

- 機械強制: **planned**（遅延グローバルの禁止＝CNF-002、出力の集約＝RS-014。「合成が明示的か」はレビュー事項）

### ARC-007 — 既定で決定的である

中核と UI は、現在時刻・乱数・既定ロケール・環境変数・ファイル・スレッド・プロセス状態を**直接読まない**。
これらはポートか明示的な引数から入る。読んでよいのは **`adapters-x11`・`adapters-windows`・`store` の 3 区画**であり、
そのことは「レビューの約束」ではなく、**その区画だけ禁止を適用しない**という検査器の設定の差分として残す。

NeNe Docket では決定性が**正しさそのもの**である。同じジャーナルの集合を併合すれば、どの機械でも同じ状態が出なければならない（FR-008）。
併合は core の純関数で、時刻も乱数も読まない。操作に付く時刻は、操作を作るときにポートから**値として**受け取る。

- 機械強制: **active**（CNF-012 の字句検査。`std::time` / `std::env` / `std::fs` / `std::thread` / `rand` 等の名前を 3 区画の外で拒む。合成ルートは `std::env::args` だけを読める）
- 不能: マクロ・別名・間接呼び出しを通した到達は字句では見えない。中核は `#![no_std]` で構造的に塞ぐ（ARC-003）が、UI は `std` を使うので字句検査だけが残る
- 補足: テストにも同じ禁止を適用する。**テストが実時刻を読むことも決定性の破壊である。**

### ARC-008 — 境界は一度だけ検証する

外から来た値（ジャーナルのレコード・設定ファイル・他人のアカウント情報・OS からの文字列）は、最初の自前の境界で検証し、その場で core の型へ変換する。
検証前の生の値を中核へ流さない。UI と永続化で**違う規則の検証を二重に書かない**。

- 機械強制: **planned**（レビュー事項）
- 補助: RS-001 / RS-003（非公開フィールドの newtype と唯一のファクトリ）が、検証を通らない値の生成を難しくする

### ARC-009 — 永続化の契約は版を持つ

ジャーナルの形式・設定ファイル・外部契約は明示的な版を持ち、移行規則を決める。読めない版は既定値へ黙って落とさず、型のある失敗として返す。
直列化の型は core の型と分ける。

ジャーナルは**他人の機械が書いた古い版**を読む場面が常にある（FR-007）。新しい版の書き手は、古い読み手が読める範囲を壊さない。
壊すなら版を上げ、古い読み手には「読めない版」として示す（FR-014）。

- 機械強制: **planned**

### ARC-010 — 期待される結果は型で表す

期待される失敗・検証エラー・非互換は、閉じた `Result<T, E>` で返す。panic はプログラム上の欠陥に限る。
`Option`・`bool`・文字列で複数の業務的な結果を表さない。

- 機械強制: **planned**（panic の禁止＝RS-005。失敗の意味分類はレビュー事項）

### ARC-011 — UI は状態を描き、意図を発行する

UI 層は、application が作った値を描き、利用者の操作を意図として渡すだけを行う。
整形の判断・状態遷移・永続化の呼び出し・併合を UI に置かない。表の行の並びも、セレクトボックスの選択肢も、application が作った値を描く。

- 機械強制: **planned**

### ARC-012 — アーキテクチャは利便性に優先する

道具の近道・crate の便利機能・最適化が、状態の所有者・モジュールグラフ・契約の境界を迂回することを許さない。
アーキテクチャが間違っているなら ADR で明示的に変える。ユーティリティを装った局所的な例外を作らない。

- 機械強制: **不能**（判断そのものが対象。QLT-010 の手続きで担保する）

### ARC-013 — 外部依存は許可制

- 依存を足すときは ADR を 1 本立てる。中核（core / application）・`store`・xtask は**依存 0** である
- X11 と描画は `x11rb` と `cairo-rs`、Windows は `windows` だけ（[ADR 0002](adr/0002-no-toolkit-x11rb-cairo-win32-direct2d.md)）。UI ツールキットを入れない
- 署名（FR-010）の依存は別の ADR で 1 つだけ足す。それまで権限は無い
- バージョンに `*` を書かない（`clippy::wildcard_dependencies`）。版の固定は `Cargo.lock` の仕事であり、マニフェストに `=` を書かない
- 内部クレート（`publish = false`）同士の path 依存には版を書かない。`deny.toml` の `allow-wildcard-paths = true` はこれだけを通し、外部 crate の `*` は `wildcards = "deny"` が拒む（nene-ruler Issue #26 の継承）
- `Cargo.lock` をコミットする。ゲートは `--locked` で走り、lock が更新される状態でのゲート通過を拒む
- ライセンスは**許可制**である。`deny.toml` の `allow` に**実際に使っているものだけ**を書く。
  `make deny` は `--deny license-not-encountered` を付けて走るので、使っていないライセンスを先回りで許可すると落ちる

- 機械強制: **active**（`wildcard_dependencies`・`--locked`・cargo-deny のライセンス／脆弱性／重複版／取得元・CNF-013 の依存 0。実測は P-22 / P-24 / P-25 と [gate-proofs](quality/gate-proofs.md) 第 8 節）

## 2. 強制を置く順番

規則は、確実に効く**いちばん早い層**に置く。

1. 言語の型・可視性・網羅性
2. cargo のクレートグラフ
3. lint（forbid 層 → deny 層）
4. 規約検査（`xtask`）
5. 依存の許可制（cargo-deny）
6. CI の必須 check
7. まだ自動化できない判断だけをレビューへ

レビューだけの強制は一時的な状態であり、[QUALITY_GATES.md](QUALITY_GATES.md) に `planned` として残す。
