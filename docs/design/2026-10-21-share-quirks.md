# NAS / SMB の癖の一覧と、守り（Issue #76・2026-10-21）

施主 2026-10-21「NAS の癖 … も考慮予定にして」。共有フォルダの上の追記専用ジャーナル（ADR 0004）が前提にしていることを、NAS / SMB は守らないことがある。知っている癖を一覧にし、設計で避けられるものは避け、避けられないものは検出して示し（FR-014）、残りは許容と明記する。各行に **避けた / 検出して示す / 許容と明記** のどれかが付く。

## 表

| 癖 | いまの前提と形 | 守り | 試した場所 |
| --- | --- | --- | --- |
| SMB クライアントの属性キャッシュ（`actimeo` 1 秒程度）で、他人のジャーナルの `stat` の大きさが古い | 読み直しは大きさを見ない。前回の読み位置から開いて EOF まで読み、読めた分が伸び（`journal_file::read_since`） | **避けた**（大きさを信じない）。キャッシュの分の遅れ（1 秒）は 3 秒の刻みの中 | `other_journals::tests`・`damage::tests`（切り詰め・0 埋め） |
| ディレクトリの一覧のキャッシュで、新しいアカウントの `journal/<id>.v1.log` や `keys/<id>.v1.pub` がしばらく見えない | 読み直しごとに一覧（スレッドの側・Issue #75）。見えた時から読む | **許容と明記**: 新しい参加者の最初の操作は、一覧に見えるまで（数秒）届かない。一覧はフレームの外なので重さは無い | — |
| `rename` が原子的でない・開いている相手へ上書きできない（Windows 側） | 置き換えは `replace_file`（一時名 → rename・再試行・Issue #79）。読み手は途中の形を壊れとして捨てる（スナップショットは検査和・Issue #77 / #81） | **検出して示す**（再試行の後に失敗を示す）＋ **避けた**（読み手は捨てる） | `retry::tests`・`replace::tests`・`damage::tests` |
| `fsync` が無視される NAS | `sync_data` で永続のつもり。NAS が無視すれば、停電で最後の数秒が消える | **許容と明記**（SPECIFICATION 第 2 節: 失う幅は「数秒」。NAS がキャッシュを失えばその分） | — |
| 大文字小文字を区別しない（SMB / NTFS / macOS） | store が作る名前は全部小文字の ASCII（アカウント ID は小文字の 16 進・`docket.v1.txt` 等・添付のフォルダは `<作成者>-<連番>`）。添付の写しは `<連番>-<元の名前>` で、連番が違えば大文字小文字だけ違う名前も衝突しない | **避けた** | `file_journal::tests::every_name_the_store_makes_is_lowercase_ascii` |
| 使えない字（`< > : " / \\ \| ? *`）・制御文字・末尾の `.` と空白・予約名（`CON` など）・長い名前 | 添付の元の名前は `safe_name` で直す（Issue #74: `_` に置き換え・末尾を落とす・予約名に `_`・120 バイトに切る） | **避けた**。経路の長さ（Windows の 260）は台帳のフォルダの深さ次第で **許容と明記** | `core::attachment::tests` |
| oplock / lease で他プロセスの追記が数秒遅れて見える | 3 秒の読み直し。遅れは次の刻みで届く | **許容と明記**: 「届くまで数秒」（ADR 0008） | Xvfb の 2 プロセス（gate-proofs 第 14 / 45 節。ローカルなので遅れは無い） |
| 時刻（mtime）が機械ごとにずれる・NAS では粒度が粗い | 順序は論理時計（ADR 0004）。伸びは読み位置。mtime / atime / ctime はどこでも読まない | **避けた**。CNF-015 がどのクレートでも `.modified()` / `.accessed()` / `.created()` / `set_times` / `FileTimes` を拒む | `xtask`（`cnf015_*`）・`make conformance` |

## 施主の NAS で確かめること（結果はここと gate-proofs 第 49 節に足す）

- 機種・SMB の版・マウントの設定（Linux なら `mount | grep cifs` の `vers=` / `actimeo=` / `cache=`、Windows なら SMB 3 かどうか）
- `--probe-share <台帳>` の 4 つの数（Issue #75）
- 2 台から同時に編集する: 片方で追加し、もう片方に何秒で届くか（10 回の最大）。両方で続けて 1 分操作し、壊れた行の数が 0 のまま
- 新しいアカウント（3 台目）が最初の操作をしてから、先の 2 台に見えるまでの秒数（一覧のキャッシュ）

## まだ

- 属性キャッシュと一覧のキャッシュの遅れは、このコンテナでは出ない（ローカルディスク）。数字は施主の NAS で
- `fsync` を無視する NAS は検出できない（検出する手段が無い）
